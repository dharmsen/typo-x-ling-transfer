# Zero-Compute Cross-Lingual Transferability Estimation Using Typological Feature Proxies

Official implementation of LINK-TODO: the paper's public URL will be added
here once the submission is public.

The paper asks how far typological features alone go in predicting bilingual
transfer: how well ability learned in one language carries to another. Using
the ATLAS bilingual-transfer matrix ([arXiv:2510.22037](https://arxiv.org/abs/2510.22037)),
digitized for the 24 languages that survive a Grambank coverage floor, it shows
that a tuned random forest over Grambank and WALS features predicts transfer
for held-out languages with a leave-one-language-out correlation of ρ = 0.705,
and that the empirical dominance of English as a transfer source partly
reflects script, genealogical, geographic, and resource confounds. Once an
estimated bias layer is removed, the residual ranking of best sources flips
from English to Marathi and Filipino. This package regenerates every number,
table, and figure in the paper from the raw CLDF data.

## Requirements

- [uv](https://docs.astral.sh/uv/) and git. uv provisions Python 3.12 itself.
- Set up the locked environment once:

```bash
uv sync
```

`uv.lock` pins the environment the paper used: Python 3.12, scikit-learn 1.9,
NumPy 2.5, pandas 3.0, SciPy 1.18. The engine's own tests run in seconds:

```bash
uv run python -m pytest -q
```

### Data

Data is fetched automatically the first time a step needs it and skipped when
already on disk. Nothing below needs to be fetched by hand.

| Data | Size | How it arrives | Needed by |
|---|---|---|---|
| Grambank v1.0.3 CLDF | ~52 MB | shallow clone of `github.com/grambank/grambank` at tag `v1.0.3` into `data/grambank/` | most steps |
| WALS CLDF | ~5 MB | shallow clone of `github.com/cldf-datasets/wals` into `data/wals/` | most steps |
| Wikipedia article counts | 38-row CSV, shipped | frozen snapshot `data/wikipedia_articles.csv` is part of the repo; the fetcher runs only if it is missing | metadata and bias steps |
| Wikipedia lead-paragraph text | ~28 MB uncompressed, 24 editions | one-time fetch of 2000 lead paragraphs per edition, about 30 minutes; not shipped | only `a_extra_prepare` and `a_extra_run` |

Shipped frozen inputs, no fetch involved: `data/blt_ground_truth.csv` (the
digitized ATLAS matrix), `data/atlas_languages.csv`, `data/scripts.csv`,
`data/iso6393.csv`, and the two frozen Wikipedia snapshots above. Everything
else under `data/` is regenerated by the steps.
The WALS clone follows the moving `master` branch of `cldf-datasets/wals`
(Grambank, in contrast, is pinned to tag `v1.0.3`), so upstream CLDF data may
drift and a fresh-clone verify failure in CLDF-dependent steps may indicate
upstream data movement, not a code error.

## Reproducing

All commands run from the repository root. `run.py` is the single entry point;
34 steps are declared in `configs/experiments/` and grouped into four presets
in `configs/presets.yaml`.

```bash
uv run python run.py --list           # presets and all step ids
uv run python run.py --dry-run --preset main   # print commands, run nothing
uv run python run.py --preset smoke
uv run python run.py --preset main
uv run python run.py --preset appendix
uv run python run.py --preset all
```

| Preset | Steps | What it covers | Wall-clock |
|---|---|---|---|
| `smoke` | 2 | a fast end-to-end check of the runner and verifier | measured 7m54s on the build machine |
| `main` | 15 | every table in the paper body | 6945 s sequential total, about 2 hours, on the 13-core build machine; a reconstruction detailed below |
| `appendix` | 19 | source ablations, floors, robustness checks, appendix figures | considerably longer than `main`: it contains the one-time Wikipedia text download of about 30 minutes and a long-running permutation-null figure that refits the model for each of its B = 200 null permutations. No end-to-end time is claimed. |
| `all` | 34 | `main` followed by `appendix` | same as above; use this on a fresh clone |

The `appendix` preset assumes `main` has already run on the same checkout:
several appendix steps aggregate main-preset outputs. If a prerequisite is
missing, the runner refuses and names the step to run first. On a fresh clone,
use `all`.

Single steps run by id, comma-separated for several, with prerequisites
checked before anything executes:

```bash
uv run python run.py --step e1_stats
uv run python run.py --step e1_tiers,e3_ood_taxonomy
```

An interrupted run can be resumed the same way: outputs of completed steps
stay on disk, and the remaining steps can be run directly via
`--step id1,id2,...`.

Each step runs as a subprocess from the package root, with data roots pointed
at `./data`. Per-step wall times are printed as `[done]` lines and full output
is written to `outputs/logs/<step>.log`.

## Verifying

`--verify` runs each selected step and then compares its declared tables
against the canonical copies in `references/`, which are byte-identical to the
tables reported in the paper. Column names and row counts must match exactly,
text cells must match exactly, and numeric cells are compared with
`rtol = atol = 1e-3`, with NaN equal to NaN. The runner prints one PASS, FAIL,
or SKIP per step, where SKIP marks a step that declares no comparison, and
exits non-zero if any step failed.

```bash
uv run python run.py --preset smoke --verify
uv run python run.py --preset main --verify
uv run python run.py --step e1_stats --verify
```

On the build machine the regenerated main-preset tables matched the references
essentially exactly, with a maximum observed absolute difference of about
4e-16. Cross-platform float variation, from other hardware, BLAS builds, or
library versions, is what the 1e-3 tolerance covers; bit-exact agreement on
other machines is not guaranteed.

Two verification caveats are data drift, not code errors:

- The five extra distance baselines (`a_extra_prepare`, `a_extra_run`) depend
  on live Wikipedia text corpora that cannot be shipped. The shipped
  `data/wikipedia_text_manifest.csv` documents the sha256 of the corpora used
  at paper time. Re-fetched corpora drift over time and are expected to
  produce slightly different numbers, so a verify FAIL on these steps means
  the input corpora moved, not that the code is broken.
  Run them with `uv run python run.py --step a_extra_prepare,a_extra_run --verify`.
- `data/wikipedia_articles.csv` is a frozen snapshot input. Deliberately
  re-running `uv run python data_setup/download_wikipedia.py` overwrites it
  with current counts and invalidates exact verification of the metadata and
  bias steps. Recover the snapshot with
  `git checkout -- data/wikipedia_articles.csv`.

## Results

Headline numbers, each paired with the command that regenerates it. All
correlations are Pearson ρ.

| Result | Value | Regenerates with |
|---|---|---|
| Tuned RF, Grambank + WALS, leave-one-language-out | ρ = 0.705, true R² = 0.492; permutation p = 0.005 against a null with mean −0.007 at B = 200; 95% CI for ρ [0.51, 0.82] | `uv run python run.py --step e1_stats` |
| Grambank-only tuned RF, LOLO | ρ = 0.780, R² = 0.607 | `uv run python run.py --step a_sources_grambank` |
| Out-of-distribution taxonomy | LOSO macro ρ = 0.776, LOFO macro ρ = 0.729 | `uv run python run.py --step e3_ood_taxonomy` |
| Leak-free per-fold top-k selection, k = 200 | LOLO ρ = 0.710 | `uv run python run.py --step e4_leakfree_sweep` |
| Best transfer source | English leads every BTS-scale operationalization; the debiased residual flips to Marathi and Filipino, a diagnostic of bias in the matrix rather than a recommendation | `uv run python run.py --step e5_rankings` |

Some of the steps listed above (`e4_leakfree_sweep`, `e5_rankings`) refuse to
run standalone until their prerequisites have run once; the runner names the
missing step, and preset runs handle the ordering automatically.

The 6945 s figure for the full `main` preset is a reconstruction from the
build machine, not a single measured end-to-end run: the first full pass took
7124 s, `e1_stats` was then re-run at the canonical `B_boot = 2000` in 3471 s,
and the sequential total is 7124 - 3650 + 3471 = 6945 s, about 1 hour 56
minutes, on the 13-core build machine.
The preset-level timing record for these runs is
`outputs/logs/main_timing.txt`, and each step's own output lands in
`outputs/logs/<step>.log`.
Of the 34 steps, 29 declare comparisons the verifier checks and all 29
verified PASS on the build machine: 28 against reference tables plus one
parsed bias-terms log check.
The remaining five (`e5_debias_atlas24`, `e5_full_rankings`,
`a_permutation_null_fig`, `a_extra_prepare`, `a_transfer_matrices`) produce
artifacts without declared comparisons: stdout LaTeX, figures, or intermediate
matrices.
Steps run sequentially.

## Models

There are no pretrained artifacts. No weights ship with the repo and nothing
is downloaded from a model hub. Every model, including the tuned random
forests behind the headline numbers, is retrained from the raw Grambank and
WALS CLDF tables by the step that needs it. The only shipped analysis
artifacts are the frozen inputs listed under Requirements and the canonical
tables in `references/`.

## Running your own experiments

Scripts live in three directories: `pipeline/` (shared libraries),
`experiments/` (analysis entry points, incl. `run_experiments.py`), and
`figures/` (plotting). Every script can also be run directly, e.g.
`uv run python pipeline/fit_models.py --model staged --sources grambank,wals`.

Steps are plain YAML files in `configs/experiments/`; the file name is
arbitrary and the `id` inside is what presets and `--step` refer to. To add
one, copy an existing config, edit it, and run it directly or through a preset:

```bash
cp configs/experiments/e1_stats.yaml configs/experiments/my_exp.yaml
# edit configs/experiments/my_exp.yaml
uv run python run.py --step my_exp --dry-run
uv run python run.py --step my_exp
```

To run it as part of a preset, append the id to the preset's list in
`configs/presets.yaml`. Schema of a step file:

| Field | Required | Meaning |
|---|---|---|
| `id` | yes | unique step identifier used by `--step` and presets |
| `command` | yes | argv list, run as a Python subprocess from the package root with `GRAMBANK_DATA` and `WALS_DATA` pointed at `./data` |
| `description` | recommended | one-line human description |
| `data` | no | data dependencies among `grambank`, `wals`, `wikipedia_counts`, `wikipedia_text`; missing data is fetched before the step runs |
| `prerequisites` | no | step ids whose outputs must already be on disk; the runner names the missing one if not |
| `outputs` | no | files expected on disk after the step; the runner fails if any are missing, and prerequisites check against these |
| `verify` | no | outputs to compare against `references/` when `--verify` is given |
| `verify_stdout` | no | special log-parsed check; the only current value is `bias_terms` |
